# 从 MD5 到 HMAC：MiniPay 全关卡学习历程

> 本文从个人 Notion 学习笔记精选整理，记录了 v1 → v4 Pro 四个关卡的能力爬坡过程。v4 Pro 的详细技术复盘见 [01-抓包通关记录](./01-抓包通关记录.md) 与 [02-proof算法还原记录](./02-proof算法还原记录.md)。

## v1：MD5 + 盐值入门

最基础的签名题，但暴露了真实的基础短板：

- MD5 只认 bytes，字符串必须 `encode`；`hexdigest()` 返回 32 位小写十六进制
- **params 和 data 搞混**导致请求发不出去——params 拼在 URL 上，data 在请求体里；且有的字段是给网关看的、有的是给业务程序看的，一个都不能少
- 最大的教训：**只顾着看 jadx 猜逻辑，忘了抓包看真实请求**。App 里任何非本地的数据必然走后端，先抓包再分析

## v2：JNI 层分析入门

- `env` 是二级指针：解引用得到 vtable（函数指针数组），加偏移取函数指针再调用。`*(int (__fastcall **)(int, int))(*(_DWORD *)a1 + 676)` 这类伪 C 的读法：解引用函数指针的指针 → 传参 → 返回值强转
- **吃亏点**：双击 `+ 1352LL` 看到注释 `mp_md5_hex` 以为是 MD5，实际那是 vtable 第 169 项 `GetStringUTFChars`——IDA 的注释会骗人，偏移语义要自己算
- 认出标准 MD5 的指纹：魔法数累加器（1732584193 / -271733879…）、64 位计数器、64 字节缓冲区的流水线结构

## v3：多 ABI + CRC32 + AES 请求体加密

难度第一次跃升，三个新课题：

**多 ABI 定位**：APK 含 arm64/x86/x86_64 三份 so，同一函数基址各不相同。解法="锚点法"：先在 arm64 里认清目标函数的指纹（独特格式串如 `username=%s&enc_pwd=%s&ts=%s`），再到运行架构的 so 里 Search Strings → References 找到引用点，上滚到函数头拿偏移，`mod.base.add(0x1e60)`。

**CRC32**：认准多项式常量 `0xEDB88320`。Python 大坑：`0xFFFFFFFF` 在 Python 里是正数（无限前缀语义），每步运算后必须 `& 0xFFFFFFFF` 截断，否则与 C 的 uint32 行为对不上。

**AES-128-CBC + Base64 请求体加密**（`encryptBody` 完整还原）：
- key/iv 派生：XOR 加密存放的种子串（密钥 `0x5A`）解密后拼接 device_id → SHA-256 → 取前 16 字节（**为什么必须 SHA-256：AES-128 的 key 必须恰好 16 字节，素材长度不定，哈希定长**）
- 分组补块：`(len & 0xFFFFFFF0) + 16` 的向上取整写法
- Base64 的职责：二进制密文直接进 JSON 会产生控制字符中断传输
- 认知升级：伪 C 里 `(__int64)v15` 多半是"IDA 丢了变量名的指针"（arm64 指针 8 字节）；寄存器里有时只是长度，真字符串在缓冲区

## v4 Pro：商业化防御体系

详见两篇主文档。关键跃迁：

- **动手之前先分类**：证书校验先分清"指纹派"还是"文件派"，拆法完全不同
- **混淆代码里锚点优先、函数名靠后**：混淆名必须保留"读"的动作，顺藤摸瓜牵出整条链
- **环境类坑也记**：手机突然断网先 `adb shell settings global http_proxy` 查全局代理残留——被遗忘的 Charles 全局代理坑过一次
- **没有永远不变的参数**：GET 时代恒定的 `body=e3b0c442...`（空串哈希）在 POST 场景就是红旗；`session_id` 前多了个空格也能卡半天。**前期复现时每个"感觉不对劲"的参数点，都可能是后面卡死你的点**
- **params 陷阱**：URL 已手动拼 query 又传 `params=` → 双重 query → 服务端重算签名必然不匹配
