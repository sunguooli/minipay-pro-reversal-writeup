# MiniPay Pro 4.5 改造与验收说明

## 结论

原 `MiniPay-v4.apk` 的确没有达到任务书声称的商业化逆向难度：它是约 115 KB 的可调试 Debug 包，只有两个主要 Java 类，R8 没有形成有效混淆，Native 近似 `-O0` 且直接导出语义化算法/JNI 名称，HTTPS 还能通过改回 HTTP 绕过。原工程和原 APK 均未覆盖；新版在独立工程中重做。

新版刻意采用“**小型商业客户端骨架 + 标准且可复现的算法**”，不靠第三方库体积或大量死代码伪造复杂度。它用于训练真实调用链、R8 后定位、动态 JNI、会话生命周期、TLS、请求拦截器与协议字段恢复；不宣称达到完整银行 App 的代码规模。

## 新版结构

- 版本：`com.minipay.pro` / `4.5.0-lab` / versionCode 45。
- Release、`debuggable=false`、R8 full mode、资源压缩、三 ABI。
- 三十余个有实际职责的源码类，R8 后 DEX 定义 39 类；包括 Application graph、启动校时、Repository、API client、5 层 interceptor、TLS、Android Keystore 会话存储、模型和 UI。
- 现代登录、资产卡、月度收支、流水、加载/空/错误态、刷新、登出与隐藏训练地址入口。
- 只允许 HTTPS；固定实验室证书；Bearer Token 不进入 URL。
- 请求包含 timestamp、nonce、body hash、session/device/risk 绑定，服务端真正执行 nonce 去重和三阶段设备绑定。
- Native 在 Application 启动阶段加载，使用 `JNI_OnLoad + RegisterNatives`、隐藏符号、O2、RELRO/NOW 与栈保护；三个 ABI 的动态导出均只有 `JNI_OnLoad`。
- Android Keystore AES-GCM 保存会话；新进程启动时先重新同步服务器时间，再恢复资产请求。
- 模拟器、root、侧载、test-keys、Xposed 类框架只形成风险标签；Debugger 或 Frida/Gadget 痕迹门控 App 内登录，不用 `kill -9` 妨碍基础训练。
- 目标算法只使用 SHA-256/HMAC-SHA256；旧版 AES/MD5/CRC 源码和编译引用已移除。

## 训练难度

- 盲做预计 4–7 小时；逐级查看提示约 2–4 小时。
- 代码导航接近小型商业客户端，算法复现保持中等偏低难度。
- 学员最终应在不依赖 App 进程的情况下完成 challenge、登录、资产、第一页流水和训练回执。
- 学员包与教师包物理隔离：学员包没有源码、mapping、golden vector 或参考解法；服务端封装为独立 Windows 程序。

## 最终验收

- Gradle Release/R8/CMake 全量重建成功。
- 协议单测 5/5：黄金向量、完整业务流、nonce 重放、设备绑定、body/risk 篡改。
- APK Signature v2/v3/v4 验证通过；证书为 3072-bit RSA `MiniPay Training Lab`。
- `aapt`：minSdk 24、targetSdk 36、`debuggable=false`、`usesCleartextTraffic=false`。
- Native：arm64-v8a、armeabi-v7a、x86_64 均只导出 `JNI_OnLoad`。
- 独立服务程序实测完成登录、资产、5 条流水并返回 `MP-LAB-...`。
- Android 模拟器 fresh install/login 成功；强制停止进程后，加密会话、校时、资产和流水均恢复成功。
