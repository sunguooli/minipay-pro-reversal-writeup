## 环境与关键事实

- 练习 App：包名 `com.minipay.pro`（进程显示名 `MiniPay`），versionName 4.5.0-lab
- 设备：Pixel 6a，Android 16，Magisk root，arm64-v8a
- 后端：电脑上 Flask，`0.0.0.0:5443`，协议链 bootstrap → auth/challenge → auth/session → wallet/summary → transactions
- App 内硬编码后端地址 `192.168.56.1:5443`（虚拟网卡，真机直连不通）；服务器证书 SAN 只认 `192.168.56.1` / `127.0.0.1` / localhost，改局域网 IP 会报"无法连接安全服务器"
- 电脑/手机 IP 是 DHCP 动态分配（.3/.5/.6 会变），抓包前先 `ipconfig` 对一次
- Charles 系统级 CA 已通过 Magisk 模块装进 Android 16 真正的信任路径 `/apex/com.android.conscrypt/cacerts/5b8130c1.0`（注意不是旧路径 `/system/etc/security/cacerts`）

## 三道防御墙与拆法

| 墙 | 位置 | 拆法 |
|---|---|---|
| ① SSL Pinning | Java 层自建 TrustManager（assets/minipay.crt），`SSLContext.init` | Frida hook init 第二参数置 null（配合 Charles 解密 + 系统库里的 Charles CA） |
| ② 客户端门控 | `(c() & 65539) != 0` → RISK-21；65539=0x10003（bit0/1/16） | 不用单独拆——见下方电表 |
| ③ 服务器验签 | `X-MP-Risk` header 必须与 proof 里签的 risk 一致，否则 403 risk_mismatch | 保持所有值同源真实，只摘 Frida 位 |

## 最终方案（F:\python_code\minipay_final.js）

只需两个 hook：

1. `SSLContext.init` 第二参数置 `null`（TLS 信任交给系统库）
2. `Interceptor.attach(libmpguard.so基址 + 0x2BA4)`，onLeave `retval.replace(0)` —— 电表归零

风险值结构：`c() = d() | 电表`。d()（Java 层检测）贡献 0x80000（bit19）；电表（native `sub_2BA4`，壳子是 `sub_272C` thunk）贡献 0x2（bit1，Frida 特征位）。电表归零后全部 risk 读数 = 0x80000：

- 门控 `0x80000 & 0x10003 = 0` → RISK-21 天然不弹
- header（iC）、签名参数（dVar.c）、proof 里 risk=00080000 三方一致 → 验签通过

运行：`frida -U -f com.minipay.pro -l F:\python_code\minipay_final.js`，REPL 里 `%resume`。

## 踩坑史（每个坑 = 一条规律）

1. `init(km, null, sr)` 的 null = 系统默认 TrustManager，不是"信任所有"；且官方脚本还堵了 `HttpsURLConnection.setSSLSocketFactory` 第二入口
2. hook Java `c()` return 0 反而制造 mismatch：header（iC，现调 c()）变 0，但签名参数 dVar.c 是 final 字段里存好的旧值 0x80000 → 0 ≠ 0x80000 穿帮。教训：一致性校验下，改动面越小越好，别伪造值
3. 电表 hook 挂壳子 `sub_272C` 罩不住 `a()`（sub_1700 直接 call 真身 2BA4）→ hook 要挂真身
4. Frida 17：Python 宿主 `create_script` 不自动注入 Java bridge（报 `'Java' is not defined`），CLI 才有；`Memory.readCString(p)` 静态方法删除，要写 `p.readCString()`
5. `frida -n` 匹配进程显示名（MiniPay），`-f` 匹配包名；`frida-ps -U | findstr -i xx` 先确认
6. Windows 控制台快速编辑模式会冻结 Flask 后端（点一下窗口就卡死，按回车才吐日志）
7. `a()`（sub_1700）签名 = `MP2\nmethod\npath\nts\nnonce\nsession\ndevice\n%08x(risk)\nbody_hash` 然后 HMAC-SHA256；参考实现见 `04-答案与解法\reference_solver.py`
8. golden vector 是破局关键：hook `NativeBridge.a()` 只打印入参出参，一行 `args=[...,"524288"]` 直接揭示 risk 走参数传递

## 方法论沉淀

- 先静态画防御地图（jadx/IDA 半小时），再动手
- 每层改动后立刻验证该层（网络/TLS/风控/验签四层分离定位）
- 观察优先于修改：先打印真实值，再决定改什么
- 报错是对方的布防图：CONNECT Failed=TLS 层、RISK-21=门控、risk_mismatch=验签一致性
- 超时=网络不通；404=服务活着路径错；字段找赋值处、方法找调用处
